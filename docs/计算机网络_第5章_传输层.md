# 计算机网络 第5章 传输层

## 5.1 传输层的功能与端口

传输层为运行在不同主机上的应用进程之间提供逻辑通信,而网络层提供主机之间的逻辑通信。传输层具有复用和分用的功能:发送方多个应用进程共用一个传输层协议(复用),接收方把收到的信息交付给相应的端口(分用)。

端口(port)是传输层与应用进程交互的接口,用 16 位端口号标识,范围 0~65535:
- 熟知端口 0~1023:如 HTTP 80、HTTPS 443、FTP 21、DNS 53、SMTP 25。
- 登记端口 1024~49151:给没有熟知端口的应用使用。
- 短暂端口 49152~65535:客户端临时使用,通信结束后即收回。

套接字(socket)= 主机 IP 地址 + 端口号,唯一标识网络中一个通信端点。

## 5.2 UDP 协议

UDP(User Datagram Protocol)主要特点:
1. 无连接,发送数据之前不需要建立连接。
2. 尽最大努力交付,不保证可靠交付。
3. 面向报文:对应用层交下来的报文,既不合并也不拆分,保留报文边界,一次交付一个完整的报文。
4. 没有拥塞控制,网络拥塞时不会降低源主机的发送速率,适合 IP 电话、实时视频会议等实时应用。
5. 支持一对一、一对多、多对一和多对多的交互通信。
6. 首部开销小,只有 8 个字节。

UDP 首部共 8 字节:源端口(2 字节)、目的端口(2 字节)、长度(2 字节)、检验和(2 字节)。检验和用于检验整个 UDP 报文段在传输中是否出错,若接收方发现检验和有错就丢弃该报文。

## 5.3 TCP 协议的主要特点

TCP(Transmission Control Protocol)的主要特点:
1. 面向连接:使用前必须先建立连接(三次握手),使用后释放连接(四次挥手)。
2. 点对点:每条 TCP 连接只能有两个端点。
3. 可靠交付:保证传送的数据无差错、不丢失、不重复、按序到达。
4. 全双工通信:连接的两端都设有发送缓存和接收缓存。
5. 面向字节流:把应用程序交下来的数据看成一连串无结构的字节流。

TCP 连接的端点叫套接字(socket)。每一条 TCP 连接被通信两端的两个套接字唯一确定。

## 5.4 可靠传输机制

序号与确认:TCP 对每个字节编号。首部中的确认号字段表示期望收到对方的下一个字节的序号。TCP 采用累计确认方式。

超时重传:发送方每发送一个报文段就启动一个定时器,超时未收到确认就重传。超时时间 RTO 根据往返时间 RTT 动态计算:RTO = 加权平均往返时间 RTTs + RTT 偏差 RTTd × 4。

快速重传:接收方收到失序报文段后立即发送重复确认;发送方一连收到 3 个重复确认就立即重传对方尚未收到的报文段,不必等超时。

滑动窗口:发送窗口表示在没有收到对方确认的情况下,发送方可以连续把窗口内的数据都发送出去。凡是已经发送过的数据,在未收到确认之前都必须暂时保留。收到新的确认后窗口向前滑动。接收方通过确认报文中的窗口字段(rwnd)进行流量控制,告知发送方自己的接收缓冲区大小,防止对方发送过快导致溢出。

## 5.5 三次握手与四次挥手

建立连接(三次握手):
1. 客户端发送 SYN 报文段(SYN=1,seq=x),进入 SYN-SENT 状态。
2. 服务器回复 SYN+ACK 报文段(SYN=1,ACK=1,seq=y,ack=x+1),进入 SYN-RCVD 状态。
3. 客户端发送 ACK 报文段(ACK=1,seq=x+1,ack=y+1),双方进入 ESTABLISHED 状态。

需要三次握手的原因:防止已失效的连接请求报文段突然又传到服务器,产生错误和资源浪费。

释放连接(四次挥手):
1. 客户端发送 FIN 报文段,进入 FIN-WAIT-1 状态。
2. 服务器回复 ACK,进入 CLOSE-WAIT 状态;客户端收到后进入 FIN-WAIT-2 状态(半关闭:客户端到服务器方向的数据已停止)。
3. 服务器数据发送完毕后发送 FIN 报文段,进入 LAST-ACK 状态。
4. 客户端回复 ACK,进入 TIME-WAIT 状态,等待 2MSL 后关闭;服务器收到 ACK 后立即关闭。

TIME-WAIT 等待 2MSL 的原因:保证最后一个 ACK 能到达对方;让本连接中产生的所有报文段在网络中消失,防止影响新连接。

## 5.6 拥塞控制

TCP 的拥塞控制包含四种算法:慢开始、拥塞避免、快重传、快恢复。

慢开始:连接建立初期,拥塞窗口 cwnd 从一个很小的值(1 个 MSS)开始,每收到一个确认 cwnd 就增大,即每经过一个传输轮次 cwnd 加倍(指数增长)。

拥塞避免:cwnd 超过慢开始门限 ssthresh 后,每经过一个轮次 cwnd 只加 1(线性增长,加法增大)。

出现超时:把 ssthresh 设为当前 cwnd 的一半,再把 cwnd 重新置为 1,执行慢开始(乘法减小)。

快重传与快恢复:收到 3 个重复确认时执行快重传,随后把 ssthresh 和 cwnd 都设为当前 cwnd 的一半,进入拥塞避免阶段(快恢复),而不是从 1 开始慢开始。

发送方的发送窗口取拥塞窗口 cwnd 和接收方接收窗口 rwnd 中较小的一个。
